Public API: Three Worked Examples per Function

Purpose

This catalog is the final reference module in the tutorial sequence. It mirrors the public API and gives three pedagogically distinct examples for every exported function: a minimal use, a realistic agronomic use, and a more demanding or discrepant use whenever that distinction is meaningful.

The catalog is deliberately different from the focused tutorials. The focused vignettes use eval = TRUE by default so that readers see real tables, figures, diagnostics, and model objects. This catalog contains more than two hundred example calls, including optional heavy backends and deliberate failure/safeguard cases. Therefore, the catalog displays its examples without evaluating them during vignette build. Run the examples selectively after completing the corresponding focused vignette.

The examples are teaching material, not numerical validation evidence. Runtime validation is performed separately through tests/testthat/, backend golden tests, frozen datasets, and the simulation battery described in 18-validation-reproducibility.Rmd.

How to use this catalog

Do not read the API alphabetically from beginning to end on a first pass. Start from the scientific question and move to the relevant function family.

The three-example grammar

For each function, interpret the three examples as a progression rather than three recipes to copy blindly:

  1. Example 1, minimal: shows the smallest scientifically coherent call.
  2. Example 2, applied: changes treatment structure, backend, family, or inferential target to represent a realistic agronomic question.
  3. Example 3, stress/sensitivity: demonstrates imbalance, alternative coding, covariance complexity, a diagnostic case, or an explicit safeguard when useful.

When an example is computationally intensive, first reproduce the smaller executable example in the focused vignette. Then increase bootstrap replications, MCMC iterations, spatial complexity, or covariance rank for the final analysis.

Read the output in four layers

Regardless of function family, interpret results in this order:

  1. Design layer: does the model respect randomization and the experimental unit?
  2. Fit layer: did estimation converge and is the requested structure identifiable?
  3. Inference layer: what estimand, uncertainty measure, multiplicity rule, or predictive target is being reported?
  4. Scientific layer: is the estimated effect large, plausible, stable, and useful on the agronomic scale?

The catalog starts below. For conceptual explanations and complete interpretations, return to the focused vignette listed for that function family.
