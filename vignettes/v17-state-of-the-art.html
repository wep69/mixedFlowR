1 Purpose

mixedFlowR is not intended to replace the mature statistical engines on which it depends. Its role is to connect experimental design, model specification, diagnostics, inference, sensitivity analysis, specialized agronomic structures, and communication through a coherent interface.

This vignette positions the package within the contemporary R mixed-model ecosystem and explains where specialized backends remain authoritative.

Metadata snapshot. Package versions in this vignette were checked against the official CRAN package pages on 2026-08-18. Package versions change; use packageVersion() to document the versions actually used in an analysis.

2 1. Learning objectives

You will learn to:

  • distinguish orchestration from estimation;
  • understand the primary role of each backend;
  • identify areas where backend semantics differ despite a common wrapper;
  • recognize the strengths and limitations of a unified API;
  • decide when direct backend use is more appropriate;
  • document package-version provenance.

4 3. mixedFlowR’s architectural role

The package follows this architecture:

experimental design
        |
        v
mixedFlowR specification / audit
        |
        +---- lme4
        +---- nlme
        +---- glmmTMB
        +---- robustlmm
        +---- gamlss
        +---- brms
        +---- SpATS
        +---- sommer
        |
        v
diagnostics + inference + communication

The fitted backend object is preserved inside the mixedflow_fit wrapper. This matters because expert users can still access backend-specific methods when the unified interface is not sufficient.

5 4. Core Gaussian and generalized mixed models: lme4

lme4 remains a central general-purpose engine for linear and generalized linear mixed models (Bates et al. 2015). The current CRAN branch also documents covariance-structure functionality in addition to its long-standing random-effects grammar.

mixedFlowR uses it for:

library(mixedFlowR)
mixed_blocks("LMM|GLMM|random")
#>   block                   module           function_name      status
#> 1    12        Random intercepts mixed_random_intercepts implemented
#> 2    13            Random slopes     mixed_random_slopes implemented
#> 3    17             General GLMM              mixed_glmm implemented
#> 4    18            Binomial GLMM          mixed_binomial implemented
#> 5    19               Count GLMM             mixed_count implemented
#> 6    32               Robust LMM            mixed_robust implemented
#> 7    60 Random regression curves      mixed_random_curve implemented

Representative functions include:

mixed_fit()
mixed_random_intercepts()
mixed_random_slopes()
mixed_nested()
mixed_crossed()
mixed_blup()
mixed_glmm()

5.1 When direct lme4 use is preferable

Use the backend directly when you need:

  • optimizer controls not exposed by the wrapper;
  • low-level getME() components;
  • custom deviance functions;
  • specialized profiling;
  • new covariance syntax not yet wrapped by mixedFlowR.

The wrapper should not hide advanced backend capabilities from expert users.

6 5. Residual covariance and heteroscedasticity: nlme

nlme remains especially important for Gaussian mixed models with explicit residual correlation and variance functions.

mixedFlowR delegates:

mixed_ar1(..., engine = "nlme")
mixed_car1()
mixed_heterogeneity()
mixed_nonlinear(..., engine = "nlme")
mixed_growth()
mixed_dose_response()

The distinction between nlme residual covariance and structured random components in other engines is preserved in the tutorial documentation.

7 6. Flexible GLMMs and structured covariance: glmmTMB

glmmTMB uses Template Model Builder and supports a wide set of response families, zero-inflation components, dispersion submodels, and covariance structures (Brooks et al. 2017).

mixedFlowR uses it for:

mixed_count()
mixed_beta()
mixed_zero_inflated()
mixed_toeplitz()
mixed_spatiotemporal()
mixed_spatial_covariance()

A key advantage is that conditional mean, zero-inflation, and dispersion components can be modeled separately. A key responsibility is to interpret those components separately.

8 7. Robust LMMs: robustlmm

robustlmm implements robust scoring-equation estimation for Gaussian mixed models (Koller 2016). The contemporary package includes dedicated developments in robust inference, diagnostics, and structured covariance.

The mixedFlowR layer emphasizes sensitivity analysis, not automatic replacement of classical estimates.

mixed_robust()
mixed_compare_robust()
mixed_robust_influence()
mixed_contamination()

9 8. Marginal means and trends: emmeans

emmeans supports estimated marginal means across a broad set of linear, generalized, mixed, and Bayesian model classes. It also provides contrasts, trends, and comparisons of slopes.

mixedFlowR delegates:

mixed_emmeans()
mixed_contrasts()
mixed_cld()
mixed_trend()
mixed_curve()
mixed_optimum()

The wrapper deliberately separates qualitative treatment comparisons from quantitative-response questions.

10 9. Small-sample and bootstrap inference: pbkrtest and confintROB

pbkrtest supplies Kenward-Roger and parametric-bootstrap comparison tools for appropriate mixed models. confintROB provides confidence-interval methods for classical and robust LMM estimators, including parametric and wild bootstrap and percentile/BCa options.

These tools solve inferential problems. They do not repair an incorrect design model.

11 10. Simulation residuals: DHARMa

DHARMa creates scaled simulation-based residuals for many hierarchical regression models and provides diagnostics for over/underdispersion, zero inflation, and residual spatial/temporal autocorrelation.

mixedFlowR exposes this through:

mixed_blocks("diagnostic")
#>   block             module         function_name      status
#> 1    45 GAMLSS diagnostics mixed_gamlss_diagnose implemented
#> 2    65        Diagnostics        mixed_diagnose implemented

and mixed_diagnose(..., simulate=TRUE) for supported model objects.

12 11. Distributional regression: gamlss

GAMLSS models multiple parameters of the conditional response distribution (Rigby and Stasinopoulos 2005). This is scientifically useful when treatment affects variability, skewness, or conditional quantiles as well as the mean.

mixed_gamlss()
mixed_gamlss_parameters()
mixed_gamlss_select()
mixed_gamlss_quantiles()
mixed_gamlss_diagnose()

The package does not treat GAMLSS as merely a more complicated GLMM.

13 12. Bayesian multilevel modeling: brms

brms supports Bayesian generalized, nonlinear, multivariate, distributional, and other multilevel models using Stan (Buerkner 2017).

The mixedFlowR Bayesian workflow includes:

mixed_prior()
mixed_prior_predictive()
mixed_bayes()
mixed_posterior()
mixed_pp_check()
mixed_loo()

This preserves the Bayesian sequence from prior model to posterior predictive assessment rather than reducing Bayesian analysis to a posterior coefficient table.

14 13. Spatial field trials: SpATS

SpATS models two-dimensional field trends with penalized splines (Rodriguez-Alvarez et al. 2018).

mixed_spatial_field()
mixed_spatial_surface()

This module is agronomy-specific and complements parametric spatial covariance from glmmTMB.

15 14. MET, GxE, and covariance-rich breeding models: sommer

sommer supports structural mixed models, heterogeneous/unstructured covariance, known relationship matrices, and spatial models (Covarrubias-Pazaran 2016).

mixedFlowR exposes a focused subset through:

mixed_met()
mixed_gxe()

Advanced quantitative-genetic structures can still be passed through backend-specific formulas and ... when required.

17 16. What mixedFlowR deliberately does not do

It does not:

  • choose the “best” model automatically;
  • invent a distribution from the data;
  • decide fixed versus random status without a scientific target;
  • remove outliers automatically;
  • convert every quantitative factor into pairwise tests;
  • hide backend convergence failures;
  • make posterior and frequentist intervals equivalent;
  • replace specialist backend documentation.

18 17. Important semantic differences across engines

A unified function name can hide dangerous assumptions if the level of the model is not documented.

Examples:

  • residual AR(1) in nlme is not identical to a structured random component in another engine;
  • lme4 and glmmTMB use different computational machinery for some GLMMs;
  • gamlss and brms distributional regression have different inferential frameworks;
  • SpATS spatial smoothing is not the same model as a Matérn covariance;
  • robust scoring equations are not the same as cluster-robust standard errors.

The vignettes preserve these distinctions even when the user-facing API is consistent.

22 21. Key take-home messages

  • The statistical engines remain the source of estimation authority.
  • mixedFlowR adds design awareness, workflow coherence, safeguards, and communication.
  • A consistent API must not imply that different covariance or inferential frameworks are identical.
  • Direct backend use remains appropriate for advanced features not exposed by the wrapper.
  • Package versions are part of reproducibility and should be recorded.
